# BMAD Quick Flow: Omron native completion

## Track and scope

Use the installed sanitized `bmad-suite` routing contract: Build (clarify, plan,
implement, review, present), followed by evidence-based review. No upstream prompt
payload, auto-build loop, dependencies, environment, account or VM is installed.
There was no existing project-local BMAD state to migrate. Chat is Indonesian;
repository artifacts remain English.

The task resumes existing approved work rather than defining a new backend:
CP1H X/XA and CP2E-N instruction regression, then CP1L M/L/L10, then CJ2M CPU31.

## Acceptance authority

`README.md`, `CONTRIBUTING.md`, `RELEASING.md`, and `docs/media.md` govern delivery.
Native compiler diagnostics are necessary for a native-verified target claim;
matching saved-program MCP read-back follows the existing Omron pattern. Simulator
and physical PLC tests are separate evidence levels, not publication gates.
No claim of a new independently licensed in-repo Omron backend is made.

## Build sequence

1. Inspect the actual owned native window/control tree and privileges.
2. Compile the three CP1H/CP2E inputs; capture exact target, diagnostics and files.
3. Compile CP1L M/L/L10 with their explicit variants and memory ranges.
4. Compile CJ2M CPU31; do not infer other CJ2/EM support.
5. Compare saved program instructions and CPU, record actual workflow GIFs, and
   publish only inspected/sanitized evidence with source hashes.
6. Run repository and synchronization checks; review intended publication files,
   secret/dependency/signing checks, then commit/push the feature branch.
