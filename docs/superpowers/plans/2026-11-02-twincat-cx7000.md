# TwinCAT CX7000 Backend Implementation Plan

**Historical CX7000 plan, not the current release gate.** The user authorized an installed-software-compatible target; TwinCAT RT x64 was subsequently implemented and passed native MCP acceptance on 2026-11-03. CX7000/ARM remains planned and unchecked. See [current BMAD outcome](../../../_bmad-output/delta-beckhoff-expansion.md), [the ready x64 example](../../../contoh/beckhoff/01-twincat-rt-x64-conveyor/) and [ROADMAP](../../../ROADMAP.md). The remaining original checkboxes below refer to CX7000, not an unfinished x64 adapter.


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an offline MCP backend that generates LD in TwinCAT, builds for CX7000 and verifies the vendor-produced saved logic through multi-plc-agent.

**Architecture:** Add `backends/beckhoff/beckhoff_mcp/`, backend key `twincat`, vendor `beckhoff`, prefix `beckhoff_`. Use the installed official Automation Interface and validated PLCopen exchange. Keep the router's transport and existing backends unchanged; do not launch a separate LLM runtime or treat XAE as a CODESYS ScriptEngine profile.

**Tech Stack:** Python standard-library stdio MCP, installed Windows PowerShell/COM or an already owned equivalent Windows runner, TcXaeShell.DTE.17.0, TwinCAT PLC package 7.1.3 (component 4026.27.4.0). No self-elevation or runtime activation.

**Spec:** `../../../ROADMAP.md`, sections Backend delivery contract and HMI-AI integration boundary.

## Global Constraints

- Keep the existing `wayandadang` WSL/agent environment; do not require another Windows account.
- CX7000 uses `TwinCAT OS (ARMV7-M)` according to the official Beckhoff platform matrix. Reject a missing platform; never silently build x64 as a substitute.
- No online connection, Activate Configuration, runtime restart/mode change, PLC download or I/O forcing.
- Product write operations require `--allow-write`; overwrite requires an explicit flag and backup.
- Bind each operation to the owned project/solution and native instance. Do not attach to an unrelated active IDE, accept arbitrary shell commands or publish an administrator control endpoint.
- Independent vendor export/read-back, not generated-input self-comparison, is required.
- A checked README item requires the real shared-conveyor native run; GIFs require a genuine successful sequence.

## Review Focus

- Automation Interface registered but PLC package/library missing: fail with the exact prerequisite, without installing or inventing a build result.
- Platform mismatch: reject x64/ARMV7-A when CX7000 ARMV7-M is requested.
- Imported LD has lost declarations, branches, timer/reset semantics or task call: read-back comparison must detect the loss.
- Vendor modal dialog, timeout or stale COM instance: return failure and clean up only owned resources; never retry writes blindly.
- The project builds but cannot be exported/reopened: do not report end-to-end success.

## Task 2: Implement the complete backend

**Files:** Create `backends/beckhoff/beckhoff_mcp/{__init__.py,__main__.py,server.py,ladder.py,native.py}` and `backends/beckhoff/tests/test_beckhoff.py` after Task 1 passes. If proven reusable IEC logic needs a shared module, migrate existing callers only after a reference check; do not copy the entire CODESYS backend.

**Interfaces:** Preserve `Server.call(name: str, args: dict) -> dict` and protocol 2025-06-18. `ladder.validate(pou: str, variables: list[dict], rungs: list[dict]) -> list[dict]` returns target-specific findings without writing. `native.run(job: dict) -> dict` admits only explicit offline project operations and returns real build/read-back evidence. Public tools are `list_targets`, `validate`, `new_project`, `write_ladder`, `build` and `read_program`.

- [ ] Write and run failing behavior tests for invalid/missing variables, malformed branches, unsupported target/platform, timer/counter argument errors, denied write, overwrite refusal, unresolved library and exported-logic mismatch. Do not test copied strings or mock echo as native success.
- [ ] Implement the proven XML/native write and read-back path with target identity and task/declaration checks. Do not synthesize native build counts or suppress compiler errors.
- [ ] Implement COM/process lifecycle with bounded deadlines, exact instance ownership, cleanup in failure paths and stderr-only diagnostics outside protocol replies. No online tools or arbitrary command proxy.
- [ ] Run behavior tests green and exercise the actual stdio entrypoint: initialize, list tools, validate, denied write and shutdown. Protocol success is not native build acceptance.
